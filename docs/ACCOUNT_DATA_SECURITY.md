# LocalAI 사용자별 데이터 격리 및 기록 보안

## 원칙

- 공유 가능: 설치 프로그램, 공용 실행환경, 설치된 모델, 최소한의 기계 관리 상태. 민감한 대화 및 작업 내용을 여기에 기록하지 않습니다.
- 개인 데이터: `C:\LocalAI\users\<계정>\user_data\`, 개인 기록: `C:\LocalAI\users\<계정>\logs\`, 개인 작업 파일: `C:\LocalAI\users\<계정>\workspace\`.
- 개인 폴더는 Windows 계정 SID 기반 ACL로 접근을 분리합니다. 읽기 권한은 해당 사용자, SYSTEM, 관리자 그룹에 제한됩니다. 다른 일반 사용자에게 열람 권한을 부여하지 않습니다.
- 개인 로그·설정·프로젝트·일정·실행 메타데이터는 기존 `core.vault`의 사용자 범위 DPAPI 암호화를 사용합니다. 개인 로그는 줄 단위, JSON 저장은 파일 전체 암호화입니다.
- Windows에서 DPAPI를 사용할 수 없거나 `LOCAL_AI_VAULT=off`라면 새 개인 기록을 **평문으로 저장하지 않고 실패**합니다. 개발 환경(Windows 이외)에서는 기존 테스트용 평문 동작을 유지합니다.
- 다른 계정의 데이터는 LocalAI의 API/MCP로 읽을 수 없도록 각 프로세스를 해당 Windows 계정으로 실행하며, 저장소 루트 경로를 클라이언트 입력으로 받지 않습니다.

## 공유 Ollama 로그

Ollama 서버 한 개가 여러 Windows 계정의 요청을 처리합니다. 단순히 로그 위치를 어느 계정 폴더로 옮기는 것은 개인정보 격리를 보장하지 않습니다. 이에 따라 관리형 Ollama 프로세스의 **원시 stdout/stderr는 영구 저장하지 않고 버립니다**. 각 계정에 필요한 설치·기동 실패 메시지만 기존 개인 로그에서 암호화하여 취급합니다.

이전 릴리스에서 만들어진 `C:\LocalAI\ollama\logs\server.log` 및 임시 디렉터리의 로그는 새 버전에서 더 이상 사용하지 않지만, 사용자 데이터를 임의로 삭제하지 않기 위해 자동 삭제/이관하지 않습니다. 관리자가 Ollama 중계기를 완전히 중단한 뒤 파일의 필요성과 보존 정책을 확인해 별도로 정리해야 합니다.

## 대화와 Agent 작업 공간

AnythingLLM 및 Open Interpreter는 실행 중 읽고 써야 하므로 사용자 폴더 안에 **세션 동안 평문이 남을 수 있습니다**. 서비스 종료 확인 후 DPAPI로 봉인되며, 비정상 종료 후에는 런타임 정지 확인 뒤 봉인을 재시도합니다. 실시간 완전 암호화가 적용된 저장소라는 의미는 아닙니다.

사용자가 소유한 `workspace\`의 일반 파일 자체는 의도적으로 자동 암호화하지 않습니다. 이들은 개인 ACL로 분리되지만, 필요한 경우 BitLocker 등의 디스크 암호화를 추가로 사용하는 편이 좋습니다.

## 보안 보장의 한계

- Windows **다른 일반 계정의 무단 조회 차단**을 목표로 합니다.
- 관리자 또는 SYSTEM은 접근 권한을 바꾸거나 프로세스를 제어할 수 있습니다. 특히 사용자가 로그인해 있는 동안 계정 세션이나 프로세스를 탈취하면 데이터를 읽을 수 있으므로, 악의적인 관리자·운영체제 침해까지 절대적으로 차단한다고 주장하지 않습니다.
- DPAPI 보호는 해당 Windows 계정의 인증 보안에 의존합니다. 암호화 파일은 계정 자격 증명 복구가 불가능해지면 복호화할 수 없을 수 있으므로 계정별 내보내기·백업 정책이 필요합니다.
- 프로그램 밖에서 실행하는 Ollama, Docker, 타사 프로그램이나 OS의 진단 로그는 이 변경만으로 모두 통제할 수 없습니다.
- 위 경계가 실제 Windows의 복수 계정에서 작동하는지는 계정 A/B 접근 거부, 각 계정의 파일 암호문 검사, 서비스 재시작/비정상 종료, 로그 경로 검사로 현장 검증해야 합니다.

## 수용 검증

1. 서로 다른 Windows 계정 A/B로 실행해 개인 설정·일정·로그 접근이 거부되는지 확인합니다.
2. 저장된 개인 설정과 로그를 직접 열어 DPAPI 암호문으로 저장되는지 확인합니다.
3. 암호화 비활성화 또는 Windows DPAPI 오류 시 민감 데이터 기록이 중단되는지 확인합니다.
4. 공용 `ollama/logs`에 새 `server.log`가 생성되지 않는지 확인합니다.
5. Chat/Agent가 정상 종료되면 개인 데이터의 봉인이 완료되는지 확인합니다.
6. 기존 기록을 사용자 동의 없이 다른 계정으로 이동하지 않는지 확인합니다.
