# 자막 만들기 (Tools → 자막 만들기)

영상·MP3·WAV 등의 말소리를 **이 PC에서** 받아 적어 SRT·WebVTT 자막을 만들고, 원하면 기존
[파일 번역] 도구로 번역 자막까지 만듭니다. 음성 인식은 Ollama LLM이 아니라 별도의 음성 인식
모델(Whisper, whisper.cpp 실행기)이 하고, 번역만 기존 로컬 LLM이 합니다.

```text
영상·음성 ─ ffmpeg ─▶ 16kHz WAV ─ whisper.cpp ─▶ 최초 인식(보관)
                                        │
                     의심·누락 구간만 다시 인식 ─▶ 명확히 나은 후보만 반영(판단 기록 보관)
                                        │
             환각·소리 표기 정리(근거가 겹칠 때만 삭제) ─▶ 자막 규칙으로 큐·줄 나눔
                                        │
                      원어 자막 이름.<언어>.srt ──(선택)──▶ 파일 번역 도구 ─▶ 번역 언어 규칙으로 다시 나눔
                                                                          └▶ 이름.<번역 언어>.srt
```

## 사용

- **Tools → 자막 만들기:** 파일(여러 개 가능)이나 폴더를 고르고 [자막 만들기]. 결과는 원본 옆
  `이름.<언어코드>.srt`(이미 있으면 `이름.ko (2).srt`)이며 원본과 기존 파일은 덮어쓰지 않습니다.
  [번역 자막도 함께 만들기]를 켜면 번역 언어·모델·목적을 고를 수 있습니다.
- **Tools → 파일 번역:** 번역할 파일로 영상·음성을 고르면 콘텐츠 유형이 자동으로 [자막]이 되고,
  자막 도구의 인식 설정(모델·품질·용어 힌트)으로 원어 자막을 만든 뒤 번역합니다. [원문 언어]를
  고르면 음성 언어로도 씁니다. 이 자동 설정은 일반 번역의 기본값으로 저장하지 않습니다.
- **폴더 단위:** 자막 도구에서 폴더를 고르면 하위 폴더까지 영상·음성을 찾아 각 원본 옆에 만듭니다.
  [파일 번역]에서 폴더를 고르면 영상·음성은 복사하지 않고 자막을 먼저 만든 뒤(결과 폴더 `폴더이름.<언어>`의
  같은 위치에 원어 자막) 다른 문서와 **같은 폴더 메모리**(인물·용어·줄거리)로 번역합니다. 시리즈 회차끼리
  이름 표기가 이어지고, 중단 후 다시 실행하면 번역 자막이 있는 회차는 인식부터 건너뜁니다. 엔진·모델이
  없으면 예전처럼 영상은 복사만 합니다.
- **용어 사전 수정:** 번역이 끝나면 [용어 사전 수정] 탭(번역·자막 도구 모두)에 원문 → 번역 용어가 나옵니다.
  번역을 고치거나 항목을 더한 뒤 [바꾼 용어 적용]을 누르면 **그 용어가 든 줄만** 고친 용어를 강제한 채
  다시 번역해 결과 파일을 고쳐 씁니다(단순 치환이 아니라 다시 번역하므로 조사·어순도 맞춥니다).
  [고정 용어집에도 추가]를 켜 두면 두 도구가 함께 쓰는 고정 용어집에 들어가 다음 번역부터 적용됩니다.
  고치는 데 필요한 상태는 메모리에만 두고 디스크에 남기지 않으므로, 프로그램을 다시 열면 다시 번역해야
  합니다(폴더 번역은 앞쪽 100개 파일까지).
- 같은 파일·설정으로 다시 만들면 보관한 인식 결과를 재사용합니다(형식만 바꾸거나 번역만 다시 할 때
  다시 인식하지 않음). 보관본은 계정 개인 폴더 `user_data\tools\subtitles`에 최대 14일·30개.

## 설치와 권한

| 구성요소 | 위치(공용, 관리자만 쓰기) | 고정 버전·검증 |
|---|---|---|
| whisper.cpp CPU / CUDA | `environment\speech\whisper\cpu`, `...\cuda` | `v1.9.5` 공식 릴리스, GitHub 자산 SHA-256 digest |
| FFmpeg(LGPL) | `environment\speech\ffmpeg` | BtbN `autobuild-2026-10-31-12-59`, checksums.sha256 + digest |
| Silero VAD | `environment\speech\vad` | whisper.cpp 고정 커밋의 파일, 코드에 적은 SHA-256 |
| 음성 인식 모델 | `models\speech\ggml-*.bin` | whisper.cpp 모델 표의 SHA-1 |

- 엔진은 관리자 `RUN.bat --install`이 선택형 구성요소로 설치합니다(LLMfit처럼 실패해도 다른 설치는 계속).
  관리자 계정의 자막 화면 [엔진 설치 / 복구]로도 설치·복구할 수 있습니다.
- 모델(0.5~3GB)은 설치기에서 받지 않고, 관리자가 자막 화면의 표에서 골라 받습니다. 다른 계정은
  설치된 모델을 그대로 씁니다. Ollama는 `models\manifests`·`blobs`만 읽으므로 `models\speech`를 건드리지 않습니다.
- 받는 중 중단하면 `.part`가 남아 다음에 이어 받습니다. 검증값이 다르면 지우고 실패합니다.
- NVIDIA GPU가 있으면 CUDA 빌드를 먼저 쓰고, 실패하면(드라이버·메모리 부족) CPU 빌드로 다시 실행합니다.
  공용 Ollama가 올려 둔 다른 계정의 모델을 임의로 내리지 않습니다.
- 한글 파일 이름·용어 힌트: whisper-cli는 시스템 코드 페이지로 인자를 받으므로 ASCII 작업 폴더의
  사본과 UTF-8 응답 파일(`@args.txt`)로 넘깁니다.

| 모델 | 크기 | 용도 |
|---|---|---|
| large-v3 | 약 2.9GB | 최고 정확도. '최고 정확도' 품질에서 의심 구간 재인식에도 씁니다 |
| large-v3-turbo | 약 1.5GB | **권장.** large-v3에 가까운 정확도, 몇 배 빠름 |
| large-v3-q5_0 / large-v3-turbo-q5_0 | 1.1GB / 0.5GB | 압축본(저사양) |
| medium / small | 1.5GB / 0.5GB | 가벼움(오류 증가) |

## 자막 문법 (`core/tools/subtitles.py`)

- SRT: 번호, `HH:MM:SS,mmm --> HH:MM:SS,mmm`, 빈 줄, CRLF. WebVTT: `WEBVTT` 머리, `.` 밀리초, `& < >` 이스케이프.
  둘 다 UTF-8(BOM 포함, Windows 재생기 호환). 글 속의 `-->`는 구조를 깨므로 `→`로 바꿉니다.
- 한 큐 최대 2줄. 한 줄 글자 수: 한국어·중국어 16, 일본어 13, 태국어 35, 그 밖 42(고급 설정에서 변경).
  한 줄에 들어가면 한 줄. 두 줄은 문장부호 뒤·접속사 앞을 길이 균형보다 우선하고, 기능어(the, of …)를
  줄 끝에 남기지 않으며, 일본어·중국어는 금칙(、。」 등으로 줄 시작 금지)과 조사 뒤 경계를 따릅니다.
- 표시 시간 최소 5/6초·최대 7초, 큐 사이 최소 2프레임(83ms), 0.5초 미만 틈은 이어 붙임(chaining).
  읽기 속도(한국어 12, 일본어 4, 중국어 9, 그 밖 17자/초)만큼 다음 큐 전까지 더 보여 줍니다.
- 한 문장은 되도록 한 큐에. 긴 문장은 문장 끝까지 미리 보고 두 큐로 균형 있게 나누며, 최소 표시 시간을
  채울 수 없는 조각은 앞뒤 큐에 합칩니다. 앞 큐에서 이어진 문장 꼬리는 새 문장과 섞지 않습니다.
- 번역 자막: 번역 도구는 줄 단위로 번역하므로 큐마다 한 줄로 합친 사본을 넘기고, 번역문을 번역 언어
  규칙으로 다시 나눕니다. 두 줄에 들어가지 않으면 그 큐의 시간 안에서 글자 수 비율로 둘로 나눕니다.

## 오탐지 처리 원칙 (`core/tools/speech.py`, `core/tools/asr_review.py`)

반복·감탄사·말 더듬기·비속어·비문은 **그 자체로 오류가 아닙니다.** 삭제·교체에는 근거가 겹쳐야 합니다.

| 의심 | 근거로 쓰는 지표 | 처리 |
|---|---|---|
| 반복 루프 | 같은 글자·구절 5회 이상 | 8회 이상이거나 다른 근거가 있을 때만 두 번으로 줄임, 아니면 '확인 필요' |
| 같은 문장 3회 이상 연속 | + 낮은 확신도 / 압축률 > 2.4 / 불가능한 빠르기 / 긴 구간에 글이 거의 없음 | 근거가 있을 때만 삭제, 아니면 유지·표시 |
| 무음에서 지어내는 정형 문구 | '시청해 주셔서 감사합니다'·'자막 제공 및 광고…' 등이 글의 큰 부분 + (확신도 < 0.6 또는 위 근거) | 근거가 있을 때만 삭제, 아니면 표시 |
| 낮은 확신도·높은 압축률·발화 속도 | 토큰 확률, zlib 압축률, 글의 문자로 잰 빠르기(음절 문자 1, 라틴 문자 0.4 단위, 초당 16 초과 / 5초 넘는 구간이 0.8 미만) | 표시 + 재인식 대상 |
| 다른 언어로 인식 | 구간별 문자 체계·기능어 감지 | 언어 자동 감지로 그 구간만 재인식 |
| 발언 누락 | **VAD가 말소리라고 한 1초 이상 구간에 인식된 단어가 30% 미만** | 언어 자동 감지로 그 구간만 재인식, 깨끗하고 확신도 0.7 이상일 때 **빈 곳에만 끼워 넣음** |
| 비슷한 이름 | 편집 거리(SequenceMatcher ≥ 0.8) | **보고만 함**(다른 호칭일 수 있어 통일하지 않음) |

VAD를 켜면 whisper-cli의 상세 JSON은 구간 시각만 원래 오디오 기준이고 **토큰 시각은 무음을 잘라 낸
시간**입니다(실측에서 발견: 23초에 시작한 말이 12초에 표시되고 일부 큐가 1ms가 됐습니다). 엔진은 실행 중
`vad_segment_info` 로그로 구간 대응표를 모으고, whisper.cpp와 같은 규칙으로 토큰·DTW 시각을 되돌립니다.
잘라 낸 틈에 걸린 단어 시작은 다음 발화로, 끝은 앞 발화로 보내고, 한 단어가 잘라 낸 무음을 가로지르지
못하게 하며, 문장 첫 단어만 앞 발화 끝에 남은 경우는 다음 발화 앞으로 옮깁니다.

재인식 후보 채택(`asr_review.choose`): 후보에도 근거가 있으면 기각, 원래 결과에 확신도 외 근거가 있거나
후보 확신도가 0.08 이상 높을 때만 교체, 그 밖에는 원래 결과 유지. 최초 인식 결과(`transcript.json`)와
판단 기록(`review-<품질>.json`)은 작업 폴더에 보관합니다. 품질 '빠름'은 재인식을 하지 않고, '균형'은
같은 모델로 최대 12곳, '최고 정확도'는 large-v3(설치된 경우)로 최대 24곳을 다시 인식합니다.

번역은 자막·대본 유형에서 말투·감정·표현 강도·비속어·은어·사투리·조어·말버릇을 같은 강도로 옮기고
순화·평탄화·요약·설명 추가를 하지 않도록 지시합니다. 자막 도구의 번역 목적 기본값은 '자연스러운 번역
(정보 생략 없이)'입니다. 번역 도구의 문서 메모리(요약·문체·용어·화자), 앞 문장 문맥, 원문 대조 검수와
문제 줄만 다시 번역하는 단계는 그대로 씁니다.

## 평가

```bat
python -m tools.evaluate_subtitles 기준.srt 생성.srt --language ko
python -m tools.evaluate_subtitles 기준.srt 최고정확도.srt --baseline 빠름.srt
```

WER·CER, 환각률(기준 발화 시간 밖 비율), 발언 누락률, 타임스탬프 MAE, 자막 규칙 위반 수를 출력하고,
`--baseline`을 주면 재인식·정리 전 대비 개선·악화(과잉 교정) 큐 수를 셉니다. 시각 비교는 기준 경계 앞뒤
0.5초(collar)를 빼고, 한 발화를 자막 규칙으로 나눈 큐 사이의 짧은 틈은 덮인 것으로 보며, 타임스탬프 오차는
기준 발화 단위로 잽니다(큐 단위로 재면 긴 발화를 나눈 큐마다 발화 전체와 비교해 오차가 부풀었습니다).

## 실측 (2026-11, whisper.cpp v1.9.5 · large-v3-turbo-q5_0 · CPU 4코어)

공개 다국어 음성 FLEURS(한국어·일본어·중국어·영어, 사람이 읽은 실제 녹음과 정답 전사)를 이어 붙여 언어마다
시나리오를 만들었습니다. **clean**은 발화 10개와 0.3~2.5초 간격입니다. **hard**는 음악 같은 소리 6초, 무음 8초,
잡음 섞인 발화, 다른 언어 발화 1개, 끝 무음 10초를 넣었습니다. **hard 영상**은 hard를 mp4로 감싸 ffmpeg 경로를
거치게 했습니다. 정답 시각은 발화 파일 경계(정확)를 씁니다. 지표는 발화별 CER, 발화 누락률(발화 구간 글의
CER ≥ 0.8), 환각 글자 비율(어느 발화 구간에도 없는 글)입니다. 실행 속도는 CPU에서 영상 길이의 약 1.4~3배였습니다.

| 시나리오 | 원시 Whisper | 처음 구현의 재인식 | 최종 규칙 |
|---|---|---|---|
| ko hard(한국어 속 영어) | 0.237 · 누락 17% | 0.288(악화) | **0.088 · 누락 0%** |
| ko hard 영상 | 0.235 · 누락 17% | 0.289(악화) | **0.086 · 누락 0%** |
| zh hard | 0.381 · 누락 33% | 0.262 | **0.196 · 누락 0%** |
| zh hard 영상 | 0.405 · 누락 33% | 0.286 · 환각 8.6% | **0.227 · 누락 0% · 환각 0%** |
| en clean | 0.450 · 누락 40% | 0.450 | **0.367 · 누락 30%** |
| ja hard | 0.198 | 0.334(악화) | 0.198 |
| 나머지 6개 | — | 일부 악화 | 원시와 같음 |

최종 규칙은 12개 시나리오 어디에서도 원시 결과보다 나빠지지 않았습니다. VAD를 끄면 일본어·중국어에서 무음·음악
환각(글자 비율 12%·5%)이 생기고 누락 탐지 근거(VAD 구간)도 없어, VAD 켬 + 재인식이 더 낫습니다(ko hard 0.243 vs 0.088).

VAD 감도(임계값 0.35, 최소 발화 150ms, 최소 무음 300ms, 앞뒤 여유 250ms)도 재인식까지 포함해 비교했습니다.
작은 목소리·건너뛴 발화가 있는 경우는 크게 좋아졌지만(en hard 0.194 → 0.034, en clean 누락 30% → 10%,
ko hard 0.088 → 0.048), 깨끗한 한중일 녹음은 나빠졌습니다(ja clean 0.030 → 0.095, ko clean 0.084 → 0.110,
zh hard 0.196 → 0.261). 8개 중 4개가 나빠졌으므로 **기본값은 whisper.cpp 그대로** 두고, 고급 설정의
**[작은 목소리 우선 (누락 줄이기)]**(기본 꺼짐)으로 고를 수 있게 했습니다.

| 설계안 항목 | 판단 | 근거 |
|---|---|---|
| 근거 기반 정리(반복·감탄사 보존, 근거가 겹칠 때만 삭제) | **도입** | VAD 켬: 오탐 삭제 0건. VAD 끔: 30초 무음 환각만 지움(환각 12.4% → 6.4%) |
| 의심 구간 선택적 재인식 | **수정 후 도입** | 처음 구현은 4개 시나리오를 악화. 최종 규칙은 악화 0, 다국어 누락 대부분 복구 |
| 발언 누락 탐지 | **방식 교체 후 도입** | 소리 에너지 → VAD 구간(에너지 방식은 음악에서 환각을 채택) |
| 구간별 언어 재판별 | **도입** | 다른 언어 구간을 언어 자동 감지로 다시 인식해 복구(ko·zh hard) |
| VAD 감도 조정 | **선택지로만** | 장면에 따라 크게 좋아지거나 나빠짐 |
| VAD 끄기 | **도입 안 함** | 무음·음악 환각, 누락 탐지 근거 없음 |
| 유사 명칭 보고 | **도입(보고만)** | 자동 통일은 호칭 차이를 지울 수 있음 |

실측으로 바꾼 것
- **VAD 토큰 시각 보정**(위 설명). 가짜 실행 파일 시험으로는 찾을 수 없던 문제였습니다.
- **누락 탐지를 소리 에너지 → VAD 구간으로 교체.** 에너지 기준은 작은 목소리를 놓치고 음악만 잡았고,
  VAD 없이 다시 인식하자 음악 구간에서 '자막 제공 및 광고를 포함하고 있습니다'를 지어내 채택했습니다.
- **누락 복구는 끼워 넣기만.** 앞뒤 여유분 때문에 이웃 문장을 '원래 결과'로 보고 올바른 영어 복구를 기각했습니다.
- **발화 속도는 글의 문자로.** 중국어 파일 속 영어 문장이 중국어 기준에 걸려 '불가능한 빠르기'로 기각됐습니다.
- **'긴 구간에 글이 거의 없음'도 근거로.** VAD를 끄면 30초 무음에 확신도 0.92의 'ご視聴ありがとうございました'가 생겼습니다.
- **평가 도구의 시각 지표**(collar, 발화 단위 오차).

측정하지 못한 것과 남은 한계
- **번역(LLM) 품질:** 이 환경에서 Ollama를 설치·실행할 수 없어, 번역 연결·폴더 번역·용어 수정은 실제 번역
  서비스에 가짜 모델을 붙여 동작만 검증했습니다.
- **GPU(CUDA) 빌드와 Windows 배포 자산:** Linux에서 같은 버전을 소스로 빌드해 측정했습니다.
- **VAD가 놓친 작은 목소리:** VAD 구간 목록에 없는 발화는 누락 탐지로도 찾을 수 없습니다(en clean의 남은 누락).
  Whisper가 VAD로 이어 붙인 오디오에서 문장을 건너뛰는 경우도 일부 남습니다.
- 표본이 언어당 시나리오 2~3개(합계 약 16분)라, 기준값은 실제 사용 영상으로 평가 도구를 돌려 더 다듬어야 합니다.
  실측 스크립트와 방법은 이 문서의 기준을 따르며, 같은 측정을 `python -m tools.evaluate_subtitles`로 반복할 수 있습니다.
